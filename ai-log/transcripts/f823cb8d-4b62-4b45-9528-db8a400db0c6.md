**Half-empty LV page can go live**
1. **Optional fields can all be empty.** Once `legalText` is filled, LV.lv passes with Standard showing a title and price only (no bullets, no badge) and no FAQ. Line 89 calls that the expected outcome, so after Q13 nothing stops it.
2. **No check that a market's two locales match.** If LV.en gets bullets, badge and FAQ but LV.lv doesn't, both pages pass. Today LV.en Standard has the badge "Most popular" and LV.lv Standard has none, and no rule notices.
3. **legalText can lose legal content and still pass (l.69–70, l.18).** A skipped unknown node is only a warning in an enabled market. If the withdrawal-right text arrives as a list or heading node, the page goes live without it. A single paragraph also passes, so the trial or withdrawal sentence can be missing.
4. **The API can return 0 plans.** Every card is hidden (rule 3), and rule 4 has nothing to check, so a page with no cards passes. Nothing says what happens when the build-time `/v1/plans` call fails or returns an empty list.
5. **Bullets can disappear silently (l.34).** "Empty items dropped" has no warning, so `["", ""]` renders as a card with no bullets and nothing is logged.

**Undecided for inputs outside the fixtures**
6. **Wrong types.** The build gate covers 404 and invalid JSON only. A numeric `headline`, `bullets` as a string, a non-string `text`, or `planCards` that isn't an array all have no rule.
7. **Leftover empties after dropping.** If every FAQ pair or bullet is dropped, "hidden" is implied but not stated. A `\n` inside `text` or `answer` (collapse it or turn it into `<br>`) is also undecided.
8. **Unknown fields** at the top level, in a card or in a legal node (future rich-text marks) have no rule. Ignoring them is the likely intent but isn't written down.
9. **Ambiguous cell (l.19).** "same" in the Disabled row doesn't say whether it means "pages not generated" or "errors logged as warnings", or both.

**HTML**
10. Nothing is rendered as HTML: l.41 says React escaping everywhere, and `legalText` becomes `<p>` elements. The value from the CMS that ends up in a URL, `planKey` in `returnUrl`, is safe because rule 1 drops keys that aren't in the map.
