I wrote `spec/09-test-strategy.md` (78 lines). It has the levels table, the scenario matrix with all 10 mock scenarios plus the main non-scenario cases, the E2E setup, and what isn't tested. I kept your approach and changed four things in it:

- **State machine tests:** I wrote the expected cases by hand from 04 instead of generating them. If they were generated from the machine's own transition table, they would only check the machine against itself.
- **"Only E2E catches rehydration":** that holds for reload and return from the providers, but not for Back. Playwright may not restore pages from the back-forward cache (08 says so too). Back-restore is covered by a component test that fires a fake `pageshow` event, plus a manual check.
- **`MOCK_TIME_SCALE` doesn't touch the app's timers.** It only speeds up the mock's delays. The 20 s "Still confirming", the 3 min cutoff, the 30 s `Retry-After` countdown and the redirect delay all run on the app's own clock. Unit tests use fake timers; E2E uses Playwright's `page.clock`.
- **E2E runs on one worker.** The mock keeps all its state in one shared store, so a `POST /__mock/reset` from one test would wipe another test's orders if they ran in parallel.

Other choices you may want to change:
- **Scenario selection:** E2E picks the scenario with an `nl_scenario` cookie, not the `x-scenario` header. The cookie also reaches the provider pages, and the app never has to send test headers.
- **Expiry:** the mock doesn't speed up the 5 min eID or 1 h session lifetimes. Tests fake them by reusing a completed eID session or clearing cookies.
- **Cut order:** the 14 post-slice E2E items start with the PLAN cut list, then drop the lowest-risk ones first. "`api_500` after eID" and "Back from the pay page" are kept to the end.

Six problems below. The first two would break or quietly weaken slice tests, so they matter most.

**04 invariants with no test**
- **Inv. 2 (trust order):** every case has only one source of context. No test has stored context and the URL query disagree, so an app that always reads the URL passes. No test checks that `cancelled=1` is only a hint: e.g. `cancelled=1` while the server says `paid` or `pending` should not show PaymentFailed.
- **Inv. 5 (context survives redirects):**
  - Nothing asserts that `utm_*` is in the `returnUrl`.
  - The orderId carried through IdentityLost → Verify → PaymentReturn is never followed. The "cookie cleared" row stops at IdentityLost.
- **Inv. 6 (re-derive on every show):** the `pageshow` component case checks that on-enter runs again. It doesn't check that disabled buttons are re-enabled on restore.
- **EidCallback `history.replace` (04 rule, not numbered):** no test that Back or reload after the callback doesn't re-run it.

**E2E rows that pass with the bug still there, or can't run as written**
- **The mock providers continue on their own.** The pay, challenge and eID pages auto-continue after 1.5 s ÷ 50 = 30 ms. That beats a test's click, so "click buttons, never wait" doesn't hold.
  - "Cancel on pay page" is flaky: the auto-pay usually wins.
  - "Leave challenge" can't leave in time: the challenge approves itself first.
  - Fix: install `page.clock` on every test that visits a provider, or block the provider's auto-continue script.
- **No slice E2E reaches Polling.** In `happy` and `payment_declined` the order settles 60 ms or 20 ms after the return. PaymentReturn's single GET will usually see `paid`/`failed` already and skip Polling. Both rows only assert the final state, so broken polling still passes. The only E2E that forces Polling is `payment_slow`, which is cut 7.
- **Negative asserts that pass before the page settles:**
  - "Pay hidden" (Back from pay)
  - "no trial note" (`not_trial_eligible`)
  - "no second order" (Back, reload on Confirmed)
  - "never PaymentFailed" (`api_500`)

  Each needs a positive anchor first, e.g. "Continue payment" visible or the full price visible, then the negative check.
- **`api_500` after eID:**
  - "No order" proves nothing: the mock never creates an order under `api_500`.
  - The row can't reach Polling: with the cookie switched on Review, Pay fails before any order exists. It needs a `happy` order first, then the switch before the return.
- **Cookie cleared before return (eID part):** the mock sets `nl_session` on the eID `/complete` redirect itself. Clearing cookies before that gets a fresh session and lands on Review, not OtherBrowser. It needs the callback URL opened in a new context. The payment-return part works.
- **`payment_declined` "second orderId ≠ first":** only meaningful once the second POST has completed. Assert on the second pay-page URL, or an order count of 2, not at the click.

**Marked `S` but the slice doesn't build it**
- **Row "Double tap, reload in CreatingOrder, second tab":** needs the open order, the attempt marker and the Gate's Resume. PLAN 2.4/2.6 don't build those; 2.6 is Review → order → return → polling.
- **Legend "unit/component cases for every row are in the slice":** commits the slice to unit tests for states it doesn't build: OtherBrowser, IdentityLost, OrderNotFound, the Resume/Back flow, PaymentFailed(cancelled), and the `api_500` states VerifyError, Gate error and Unconfirmed.
